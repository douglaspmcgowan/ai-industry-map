2. How you could turn this site into an interactive map

Nine approaches, roughly from "prettier version of the site" to "research-artifact you could publish." Each card explains the tool stack, what it uniquely enables, what it costs in effort, and how it'd feel to use on this data (~200 companies, ~14 categories, mostly qualitative).

A. Tree / mindmap (Markmap)

Stack. Markmap is a single JS library that parses a Markdown outline into a collapsible, pan/zoom SVG tree. You write one .md file — headings become branches, bullets become leaves — and a build step spits out an HTML page. No database, no backend.

What it uniquely enables. Near-zero maintenance cost. If you can write Markdown, you can edit the map. Collapsing branches lets readers drill from the 14-category overview down to a single competitor without overwhelming them.

Cost. A weekend to convert your existing pages into one master outline.

Feels like. A Wikipedia table-of-contents you can fold. Great for hierarchy; silent on relationships (Anthropic→MCP→OpenAI-adopted-it is a story Markmap can't tell).

markmap.js.org

B. Node-link force graph (D3 / Cytoscape / Cosmograph)

Stack. Three flavors at different scales. D3-force is the classic — JS-animated simulation, great up to ~500 nodes. Cytoscape.js adds built-in layouts, selection, and graph-theory algorithms (shortest path, betweenness). Cosmograph is GPU/WebGL-accelerated and stays smooth at 100k+ nodes. All three take a JSON of {nodes:[...], edges:[...]}.

What it uniquely enables. Makes relationships first-class. Your site already encodes "owns," "built-on," "competes-with," "invested-in" in prose — a force graph surfaces them spatially. Clusters emerge that your 14-category split hides (e.g., the "stuff built on Claude" cluster spans 5 categories).

Cost. Week 1: extract a nodes+edges JSON from your existing HTML. Week 2: D3-force page with filters. Cosmograph only if you grow past ~1k entries.

Feels like. A constellation you can grab and drag. Satisfying, but at 200 unfiltered nodes it becomes a "hairball" — you need per-edge-type toggles and category filters to keep it legible.

D3 force Cytoscape.js Cosmograph

C. Semantic embedding map (UMAP + Deepscatter)

Stack. (1) Run each competitor's description through an embedding model (OpenAI text-embedding-3-small, or Voyage, or a local BGE). (2) Project the 1536-D vectors down to 2D with UMAP (preserves local neighborhoods better than t-SNE). (3) Optionally cluster with HDBSCAN to auto-label neighborhoods. (4) Render the scatter with Deepscatter — a WebGL library built for millions of points; overkill here, but gives buttery pan/zoom and tooltips.

What it uniquely enables. A semantic map, not an editorial one. Tools cluster by what they actually do, not by which category you filed them under. Windsurf lands next to Cursor even though you could have put them in different buckets. Surfaces cross-category similarity the hand-curated tree can't.

Cost. A day to embed 200 descriptions (~$0.05 in API cost). A day for the UMAP + HDBSCAN pipeline in a Python notebook. A day to wire Deepscatter on the front-end. Total: a long weekend.

Feels like. A star chart where proximity means similarity. Very research-paper-coded. Pairs beautifully with B — one map for relationships, one for semantics.

Deepscatter UMAP HDBSCAN

D. Infinite canvas (tldraw / Kumu / Obsidian)

Stack. tldraw SDK is an embeddable React component giving you pan/zoom, shapes, arrows, and freehand on a bottomless canvas — you can ship a read-only curated board or let visitors annotate. Kumu is a hosted SaaS purpose-built for relationship maps; you import CSV of nodes+edges and get filter UI for free. Obsidian Canvas is local-first, file-backed, not web-deployable.

What it uniquely enables. Human layout, not algorithmic. You decide what sits near what; you can group Anthropic-adjacent tools in a visual cluster that doesn't emerge from any automated layout. Annotations, arrows, and region labels are first-class.

Cost. Kumu: a weekend if your data is already in a spreadsheet. tldraw: 1–2 weeks to integrate and populate.

Feels like. A Figjam board of the industry. High-touch, low-automation; looks opinionated, which is a feature for a curated site and a bug if you want it to feel objective.

tldraw.dev kumu.io Obsidian Canvas

E. Reactive document (Observable Framework)

Stack. Observable Framework is a static-site generator built around reactive JS cells. You write a page in Markdown + JS; sliders, selects, and code blocks re-run top-to-bottom when inputs change. Builds to static HTML — no server. Integrates D3, Plot, Arrow, and DuckDB-WASM for in-browser SQL over Parquet files.

What it uniquely enables. Live exploration. A "pick your use case" dropdown that instantly refilters the map. A slider that redraws a treemap by "founded year." The reader drives the analysis instead of reading your conclusions.

Cost. 1–2 weeks if you know JS. Steep ramp if you don't — reactive data flow is unfamiliar until it clicks.

Feels like. A Jupyter notebook that reads like a magazine article. Strong research-artifact vibe. Heavier than the site you have now; lighter than a full webapp.

Observable Framework

F. Scrollytelling per-category (Pudding-style)

Stack. Scrollama (a 4KB JS lib) listens for scroll position and triggers "steps" — as the reader scrolls, a pinned graphic on the right morphs. Built on top of D3 or any canvas. Works in plain HTML, Astro, Next.js, or Svelte.

What it uniquely enables. Narrative. Good for per-category deep-dives: "how coding agents evolved 2023→2026" with a timeline that rearranges as you scroll. Terrible for the 14-category overview — scrolling is linear, the map is not.

Cost. A week per scrolly page. Custom enough that each page is bespoke.

Feels like. A New York Times data story. High production value per page, high effort, doesn't scale to "map of everything."

Scrollama Pudding (examples)

G. Tile-based zoom map (deck.gl + MapLibre)

Stack. Treat the landscape like a geographic map. tippecanoe (Mapbox's tile generator) pre-renders your 200 companies into vector tiles at multiple zoom levels. MapLibre GL serves them in the browser; deck.gl adds interactive WebGL layers on top. You place each company at its UMAP coordinates — panning + zooming feels like Google Maps, but the territory is semantic.

What it uniquely enables. True multi-scale. At low zoom you see continents (categories as labeled regions); at high zoom you see individual companies with logos and metadata. Labels dynamically decluster.

Cost. 2–3 months to build well. Overkill for 200 entries — this stack is designed for 100k+.

Feels like. "Google Maps for AI." Stunning, impressive, and disproportionate to the dataset. Worth it only if you plan to scale into thousands of entries and want a research moat.

deck.gl MapLibre GL tippecanoe

H. 3D starfield (Three.js / React Three Fiber)

Stack. Three.js wraps WebGL; React Three Fiber gives it a React component model. Each company is a glowing point in 3D space, positioned by a 3D UMAP projection. Reference: Google's 100,000 Stars visualization of the Milky Way.

What it uniquely enables. Awe. Pure aesthetic payoff — great for a landing page, portfolio piece, or tweet-able moment. Hover states, camera flights to specific nodes, constellation lines between related tools.

Cost. 3–6 months to polish. Mobile performance is a real concern; accessibility is weak (screen readers can't narrate 3D space).

Feels like. Sci-fi. All spectacle, limited info density per pixel — readers find the tool they wanted slower than on your current site. Consider it a hero visualization, not the primary interface.

Three.js React Three Fiber 100,000 Stars (reference)

I. Knowledge-graph DB (Neo4j / Memgraph + web UI)

Stack. A graph database (Neo4j or Memgraph) holds nodes and typed edges; you query with Cypher (MATCH (c:Company)-[:USES]->(m:Model) WHERE m.name = 'Claude'). Front-end either uses Neo4j's NeoDash (dashboard builder), Bloom (visual exploration), or a custom React app talking to the DB over HTTP.

What it uniquely enables. Arbitrary queries. "Every tool founded by ex-Google Brain researchers that runs on Anthropic's API and has raised over $50M" is a one-line Cypher query — impossible in every other option here.

Cost. 1–2 months initial build, plus ongoing schema maintenance. Highest ceiling, highest floor.

Feels like. A research tool, not a brochure site. Worth it only if the goal is a living dataset you'll keep querying for months.

Neo4j Memgraph
My pick for this site. B + C together. B (node-link force graph) surfaces the "Anthropic→MCP→OpenAI adopted it" kind of editorial relationships you already hand-write. C (UMAP semantic map) surfaces similarity your hand-curation can't — cross-category twins like Windsurf ↔ Cursor. Together they're a one-week build (Cosmograph + a Python notebook) that gives the site a research-artifact feel without the 3-month commitment of G or H. If you only want one: B.
